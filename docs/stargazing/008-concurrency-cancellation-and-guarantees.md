# Stargazing 8：并发、取消、停用与保证强度

日期：2026-09-04 至 2026-09-05

状态：已完成（以负面证据收束）

当前结论：有条件可行

性质：Harness 对真实 Agent 的运行控制与保证边界探索，不是生产调度器、权限系统或完整资源治理实现

## 要回答的问题

Harness 对正在运行的 Agent 究竟能观察、停止和限制到什么程度？这些能力中，哪些是 Harness 能够确定性保证的事实，哪些依赖 Agent 或操作系统，哪些只能通过提示词形成弱约束，哪些仍完全未覆盖？

本项最终需要覆盖并发、超时、取消、角色停用、工作目录与工具边界、资源计量等问题，但不会一次把它们混成一个实验。当前先讨论最阻断的小问题：**Harness 要求停止一项正在执行的 Agent 工作后，能够可靠确认什么？**

## 为什么先研究停止

Stargazing 7 已证明：Adapter 已接受但没有可靠终态的执行，在 Harness 重启后必须保持`result_unknown`，不能仅因旧进程消失而写成成功或失败。

取消和强制停止会主动制造相似窗口。如果 Harness 把“已经提出停止要求”“进程已经退出”和“工作已经取消且没有副作用”合并成一个`cancelled`结论，就可能错误重派、覆盖已有成果、漏查外部操作或错误改变委托状态。

另一方面，如果结果未知就一直把角色当成仍在执行，角色的并发能力又会被永久占用。因此，运行载体是否停止与工作结果是否确定必须先分开，后续才能讨论停用和并发。

## 已确认的语义边界

用户确认以下结论：

1. `停止事实`与`执行结果`是两类独立事实；
2. 确认旧执行载体已经停止后，可以释放角色的主动执行槽并停止继续等待该进程；
3. 停止事实本身不能证明工作成功、失败、没有产出、没有副作用或已经回滚；
4. 如果缺少可靠 Agent 终态，执行结果仍应保持未知；
5. 结果未知时不能因此自动重试，也不能自动把相关委托标记为完成、失败或取消；
6. UI 可以把两个事实组合成“已停止，执行结果未知”等易懂表达，但 Harness 内部判断和后续行为不能把它们合并。
7. 停止默认先请求正常停止；超过明确等待时间仍未停止时，再升级为强制停止；
8. 执行载体停止后需要核查已经产生的副作用，但副作用核查与停止确认、执行结果是第三类独立责任；
9. 部分副作用无法确认时，仍然释放角色执行槽，同时保留“副作用待核查或未知”，阻止自动重试，并通知相关角色或用户决策；
10. 副作用核查用于确认发生了什么，不自动产生撤销或回滚授权。

由此，`取消`首先表示一种控制意图或控制动作，而不是天然可靠的执行结果终态。是否需要在未来形成更精确的正式术语和状态模型，留到设计阶段决定。

## 对后续行为的影响

| 已知事实 | 可以支持的后续行为 | 不能据此执行的行为 |
| --- | --- | --- |
| 已确认执行载体停止 | 释放该次执行占用的角色执行能力；停止等待载体 | 声称工作没有完成、没有产出或没有副作用 |
| 已取得可靠 Agent 终态 | 记录相应执行结果，供委托发布者与主持判断 | 单独证明相关进程树、子任务或外部操作均已停止 |
| 载体已停止，但没有可靠终态 | 报告“已停止、结果未知”；进入核查或决策 | 自动重试；自动改变委托终态；假定工作已回滚 |
| 停止请求已发出，但尚未确认停止 | 继续观察或升级停止手段 | 释放执行槽；宣称停止已经生效 |

## 已确认的停止处理顺序

```text
请求正常停止
→ 在明确期限内观察是否停止
→ 必要时升级为强制停止
→ 确认 Harness 实际受控的执行载体是否停止
→ 释放相应角色执行槽
→ 核查可观察的既有副作用
→ 分别报告停止事实、执行结果和副作用状态
```

这个顺序不是在声称副作用能够被完全确认。当前需要区分三类可见性：

- Harness 直接参与的操作，可以根据自身持久化事实核对；
- 本地 workspace 等可检查范围，可以确认观察到的变化，但不自动判断变化是否完整、正确或可接受；
- Agent 绕过 Harness 直接产生的外部操作，只有在相应系统提供可靠查询或对账能力时才能进一步确认，否则必须保持未知。

执行槽释放只依赖实际受控的执行载体已经停止，不等待所有副作用变成确定状态。副作用未知是一项需要继续暴露和处理的责任，会阻止自动重试，但不会让角色永远保持忙碌。

## 当前需要避免的混淆

- 发送 SIGTERM、调用取消 API 或向 Agent 发送“请停止”都只是不同停止手段，不等于停止已经发生；
- 父进程退出不自动证明子进程、远程任务或外部工具调用已经停止；
- 退出码不能单独替代 Agent 终态。Stargazing 2 已观察到 Codex 取消后退出码为`0`但没有 turn 终态；
- Agent 自述“已取消”不能自动证明文件、网络、费用或第三方副作用没有发生；
- 角色停用是阻止新的普通工作进入和控制在途执行的角色级行为，不应与单次执行取消共用一个含混结果；
- Harness 能阻止自己再次派发，不代表能够撤销 Agent 已经直接产生的外部效果。

## 第一个候选实验问题

在一个人工、无业务副作用、可持续运行的 Agent 执行中，Harness 依次请求正常停止并在必要时升级为强制停止，能否分别取得足够的机器事实来表达：

1. 停止请求已经发出；
2. 原执行载体是否已经停止；
3. 是否取得可靠 Agent 终态；
4. 缺少终态时结果仍为未知；
5. 角色执行槽何时可以安全释放；
6. 在 Harness 直接操作、本地可检查变化和 Agent 直接外部操作三类范围内，分别能够确认哪些副作用；
7. 无法确认的子进程、远程工作或副作用能否被明确保留为未知，并阻止自动重试。

用户已经确认采用两层验证并授权直接推进至本项形成结论：先用确定性假执行器建立控制与观察基线，再用同一观察标准验证真实 CLI。假执行器不会冒充真实 Agent 证据，真实 CLI 也不会在缺少基线时独自承担所有故障归因。

当前把它收敛为两个 Probe：

1. **Probe 8.1：确定性生命周期基线。** 固定验证正常停止，以及忽略正常停止后超时升级强制停止；同时验证受控进程树、槽位释放、结果、副作用与自动重试资格彼此独立；
2. **Probe 8.2：真实 CLI 对照。** Codex 与 Claude Code 各执行一次人工长等待，使用与 Probe 8.1 相同的停止观察字段；两者不要求都进入强制停止分支，但都必须诚实记录实际停在哪一层、是否有可靠终态和哪些副作用范围仍未知。

不同角色最小并发、两个 CLI 的既有取消事实、权限和预算边界优先复用 Stargazing 2、3、6、7 的已有证据，不为了让实验数量更多而全部重跑。同角色容量和角色停用对新工作的阻止尚无直接证据，将只在确定性 Harness 调度层补充，不再为此启动额外真实 Agent。

## 当前假设

### 假设一：停止过程可以产生独立于结果的机器事实

专用 Adapter 至少能够报告停止请求、进程退出、超时和无法确认停止等运行事实，而不把它们伪装成 Agent 工作结果。

### 假设二：本地 CLI 的进程停止可以形成有限强保证

对于 Harness 直接启动并持有进程句柄或进程组的本地 CLI，操作系统可能允许 Harness 确认受控进程范围已经退出；保证范围必须明确限制在实际持有和观察的进程，不能外推到远程任务或外部副作用。

### 假设三：没有可靠终态时仍可释放有限运行资源

如果受控执行载体已经确定停止，Harness 可以释放本地执行槽，同时把工作结果保持为未知。这两个动作不矛盾。

### 假设四：副作用核查可以分级而不伪造完整性

Harness 可以可靠核对自己直接执行并持久化的操作，可以观察特定本地范围的变化，并把无法查询的 Agent 原生或外部操作明确保留为未知；不需要以“全部副作用都已确认”为停止处理完成的前提。

## 当前反证条件

出现以下任一情况时，对应假设需要收缩或否决：

1. Harness 无法区分“已请求停止”和“已确认停止”；
2. 受控进程退出后仍有由该执行产生、但 Harness 未披露的本地子进程继续运行；
3. 缺少可靠终态时被自动记录成成功、失败或已取消结果；
4. 停止后自动重派原执行，或自动改变委托完成、失败、取消、验收等语义状态；
5. 为证明停止必须访问真实项目、敏感数据、外部服务或制造不可逆副作用；
6. 实验只能依据 Agent 自然语言，而不能取得进程、协议或持久化机器事实；
7. 把某个本地 CLI 的停止能力外推成所有 Agent、远程调用或系统平台的通用保证。
8. 因部分副作用不可观察而把它默认为“没有副作用”，或反过来永久占用已经停止的角色执行槽；
9. 未经明确授权就把副作用核查扩展为自动撤销、删除、回滚或补偿。

## 初步安全边界

- 使用人工输入和临时 workspace，不处理真实项目任务；
- 不发送真实消息，不访问真实业务服务，不执行付费或不可逆外部操作；
- 在运行前检查目标 CLI 当前版本、命令参数和实际工具表面；
- 每个进程都有总时限，并预先准备明确的升级停止与进程回收路径；
- 不把 read-only、restricted、权限提示或临时目录表述成完整读取、网络或系统隔离；
- 如果观察到非预期文件读取、网络访问、子进程、后台任务或其他副作用，立即停止对应实验并记录；
- 不把既有 Stargazing 2/3 对特定实验的知情授权自动延伸到本项新的真实 Agent 运行。

用户在获知本项采用“假执行器基线 + 真实 CLI 对照”后明确同意该路径并授权直接推进。该授权仅覆盖人工输入、临时 workspace、受限工具面和有界停止的 Stargazing 8 Probe，不扩展到真实项目、敏感数据、宽泛 shell、真实外部服务或不可逆副作用。

开始实现前的本机版本观察为 Codex CLI `0.144.6`、Claude Code CLI `2.1.260`。Task 5 运行前复核时 Codex 仍为`0.144.6`，Claude Code 已变为`2.1.261`；两种产品所需 help / feature 表面均按各自精确输出形状复核。Claude 版本事实只属于运行前坐标，因为安全停止条件在其真实调用前已经触发。

## Probe 8.1：确定性基线

可丢弃 Python 探针先把停止、结果、槽位与副作用冻结为三种固定摘要：有可靠合成终态的正常停止、没有终态但在期限内停止、超时后强制停止。矛盾组合一律 fail closed，进程退出不能生成 Agent 终态。

假执行器实验证明：Harness 持有精确执行句柄时，可以先请求正常停止、到期后只向已核验身份的进程组升级强停，并在已记录 PID 与进程组都确认消失后释放槽位。无可靠终态时结果保持`result_unknown`；Harness 已记录副作用、本地 workspace 观察与外部未知分别保留；外部未知会阻止自动重试并产生固定的决策升级事实，但不会自动发送通知、回滚或作出决定。缺少 ready/effect 证据、身份不一致、残留子进程或清理失败均不产生“槽位已释放”摘要。

同一确定性执行边界还验证了两个普通角色各自容量为一：不同角色可同时持有一个执行，同一角色第二项保持待处理且未派发；停止一个角色只释放该角色槽位，新工作必须使用不同执行尝试，旧的未知尝试不会重派。普通角色的优雅停用关闭新派发但允许在途执行凭可信终态回执完成；强制停用复用同一停止控制器且不伪造终态；重新启用保留同一逻辑角色。带`host`或`supervisor`标签的角色只有先把标签转交给另一个已启用角色后才可停用。

这些都是单进程固定模型和假执行器证据，只证明 Harness 自己经由该入口作出的派发、容量与停用决定；不能证明 Agent 无法绕过 Harness 启动原生工作，也不是生产调度器或通用状态机。

## Probe 8.2：真实 CLI 对照与安全反证

Task 4 先用真实 STDIO MCP 链路和 fake CLI 完成运行前门禁。fake CLI 必须完整匹配产品专属命令，实际完成 MCP initialize、initialized、tools/list 和唯一一次`hold_until_stopped`调用；未知事件、额外参数、错误 PGID、残留进程、晚到路径或缺少终态都按固定合同处理。最终`79 tests / 0 failures`覆盖确定性合同、进程清理、调度/停用、两种 CLI 事件解析、命令表面、原始审阅证据与失败路径。这证明探针会按预定规则观察真实链路，不是实际 Agent 停止成功的替代证据。

2026-09-05 第一次 Codex 调用在当前桌面任务沙箱内运行。Codex CLI `0.144.6`在 MCP 启动前因本地状态数据库只读而失败，没有 Agent 终态或 MCP 调用；该次原始证据经独立审阅后删除。它只证明当前外层运行环境阻塞启动，不能当作停止能力结论，也没有触发自动重试。

第二次在用户明确允许的沙箱外环境运行同一受限探针。Harness 启动的 CLI 为 PID/PGID `45411`，但 Codex 随后启动的 MCP server 为 PID/PGID `45452`，属于另一个独立进程组。MCP 的唯一 hold 工具恰好进入一次，未取得 Agent 终态，也尚未发出计划中的正常停止请求；探针按预定 PGID 不一致门禁 fail closed。清理逻辑安全回收了 CLI 组，却不能在不越过身份边界的情况下把独立 MCP 组一并视为已停止，复核时该 MCP 仍然存在。

独立人工处置先用`ps`核对残留进程的完整命令身份与本项固定 MCP 一致，随后只向其独立 PGID 发送`TERM`并再次核对，确认进程消失。这个处置是安全收尾证据，不是探针成功摘要，也不允许反向声称统一父 PGID 方案可行。该次仓库外`0600`原始证据已完成独立审阅并删除；其路径、prompt、session、原始 stderr 与私有内容未进入项目记录。两个专用临时目录也已在复核内容后删除，临时 workspace 未发现未知路径变化。

这一反证足以停止 Probe 8.2：当前专用 Adapter 不能假定“CLI 与它启动的所有受控执行都位于一个父进程组”。Adapter 必须枚举并持有每个受控本地执行组，或持有远程产品提供的明确取消句柄；只有这些句柄分别完成身份核验与停止确认后，才能安全报告相应执行范围停止并释放槽位。由于当前探针没有这项能力，Claude Code 的 SG8 真实运行没有开始。Stargazing 3 已有 Claude Code CLI 进程级取消、无终态与无精确等待残留的证据，可以进入保证矩阵，但不能冒充 Probe 8.2 的同合同实跑。

## 保证矩阵

| 能力 | 证据与适用范围 | 保证类别 | 不能据此推导 |
| --- | --- | --- | --- |
| Harness 派发与角色容量 | Probe 8.1 固定调度模型；仅 Harness-mediated 入口 | Harness strong | Agent 原生工作、分布式公平或生产吞吐受控 |
| 正常停止请求 | Probe 8.1 精确句柄；SG2/SG3 各自取消事实 | OS/external conditional | 请求已发送等于载体已停止或工作已取消 |
| 超时后强制停止 | Probe 8.1 已核验的本地进程组 | OS/external conditional | 未枚举子组、远程任务或外部操作同时停止 |
| 停止确认 | 假执行器组可确认；真实 Codex 反证统一父 PGID | OS/external conditional | 仅凭父进程退出即可确认完整执行范围停止 |
| 执行结果与槽位分离 | Probe 8.1 固定合同；SG2/SG3/SG7 的无终态证据 | Harness strong | `result_unknown`等于失败，或槽位释放等于无结果/副作用 |
| Harness 已记录副作用 | Probe 8.1 固定账本范围 | Harness strong | 记录之外的操作不存在、正确或已经回滚 |
| workspace 变化 | Probe 8.1 固定 marker；SG2/SG3 文件权限事实 | OS/external conditional | 观察范围完整、成果正确或 workspace 外没有变化 |
| Agent 直接外部副作用 | 本项不制造外部操作，既有实验也无通用对账 | uncovered | 没有网络、费用、消息或第三方状态变化 |
| 决策升级 | Probe 8.1 只建立固定待决事实 | Harness strong | 已通知真人、已获批准或已经执行补偿 |
| 角色停用 | Probe 8.1 普通/受保护角色固定规则；仅 Harness-mediated 派发 | Harness strong | Agent 原生后台活动或所有远程执行被停用 |
| workspace 权限 | SG2 Codex sandbox、SG3 Claude 工具/permission denial | OS/external conditional | read-only/restricted 等于完整读取、网络或 OS 隔离 |
| 工具表面 | SG3、SG5、SG6 与 Task 4 命令/MCP 门禁 | OS/external conditional | 未暴露工具以外的所有原生能力都不存在 |
| 网络限制 | 只有 prompt 要求与局部工具禁用，没有强制断网实验 | weak constraint | Agent、provider 或子工具绝对没有联网 |
| token/成本观察 | SG2 usage 与 SG3 客户端估算；口径有限 | OS/external conditional | 观察值完整等于账号账单或可在调用前阻止超支 |
| 硬预算 | SG3 首次调用可超过极低`max-budget-usd`；本项无额外硬上限 | uncovered | CLI 预算参数是首次调用前严格成本上限 |

## 结论与适用条件

`有条件可行`。

Stargazing 8 的核心门槛是形成诚实的保证矩阵，而不是要求两个真实 CLI 都产生成功停止摘要。Probe 8.1 已证明，在 Harness 持有完整、可核验的执行句柄时，可以强制执行自身派发、容量、停用、停止后槽位释放、结果未知与禁止自动重试等边界。真实 Codex 运行则给出关键反证：CLI 与 MCP 可以位于不同进程组，统一父 PGID 假设不足以安全清理完整执行范围。探针遵守预定安全门禁并停止后续 Claude 实跑，因此本项以负面证据完成，而不是把未完成的双产品 Probe 8.2 描述为成功。

结论成立的必要条件是：每种 Agent 使用专用 Adapter；Adapter 在派发前建立能够完整注册和追踪执行组的机制，并从启动后持续发现和持有所有受控本地执行组，或持有可靠外部取消句柄；停止确认只覆盖已经逐一核验的范围；没有可靠终态时结果保持未知；外部副作用未知时不自动重试；强制、条件性外部机制、提示词弱约束和未覆盖能力向用户分开披露。

本项没有证明 Claude Code 在 SG8 同合同下的停止行为、统一跨产品进程模型、远程 Agent 取消、完整网络隔离、硬预算、生产并发、公平调度、同 workspace 并发、分布式停用或通用副作用对账。两次 Codex 原始证据均已完成独立审阅和删除；仓库只保留不含 prompt、session、私有路径、原始 stderr 或 Agent 原文的结构化事实摘要。
