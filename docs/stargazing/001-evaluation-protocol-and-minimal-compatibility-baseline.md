# Stargazing 1：评估协议与最小兼容性基线

日期：2026-09-02

状态：已完成

当前结论：可行

性质：共同评估规则与最小兼容性坐标，不是机器环境审计、Agent 能力实验或技术选型

## 要回答的问题

后续应当用什么共同尺度、证据格式和安全规则，分别验证 Codex CLI 与 Claude Code CLI 的程序化协作边界；本轮证据最少需要绑定哪些兼容性坐标，才能既可复核又不过度依赖当前电脑。

这个问题影响 Harness 核心，是因为如果两个目标 Agent 使用不同的评判尺度，或者能力结论隐含依赖大量未说明的机器环境，后续无法可靠比较、复验或提炼异构 Agent 的共同接入边界。

## 用户已确认的边界

1. 只主动记录 macOS 版本、芯片架构、Codex CLI 精确版本和 Claude Code CLI 精确版本；
2. 用户已经完成两个 Agent 的安装、登录和必要配置，这是后续实验前提；
3. 不读取或记录账号、凭证、认证文件、套餐、额度或其他登录细节；
4. 其他环境因素默认忽略，只有实际证据表明其影响结果时，才补充为特定结论的成立条件；
5. 本项不运行 Agent 工作任务，不验证 session、并发、取消、MCP、故障或恢复；两种 CLI 的首次程序化调用分别属于 Stargazing 2 和 Stargazing 3。

## 当前假设

### 假设一：最小坐标足以开始后续边界实验

使用验证日期作为证据元数据，并用“macOS 版本 + 芯片架构 + 目标 CLI 精确版本”四项坐标描述证据适用范围，足以开始 Stargazing 2 和 Stargazing 3。其他变量不需要在没有影响证据时主动盘点。

### 假设二：两种 CLI 可以共享产品问题，不必共享实现形式

Codex CLI 与 Claude Code CLI 可以使用同一组检查维度和结论词汇；它们不需要使用相同命令、session 机制、输出格式或权限模型。

### 假设三：环境变化可以局部复验

换电脑或升级环境时，先比较最小兼容性坐标，再重跑受到影响的最小实验即可；没有必要自动重做全部 Stargazing。

## 反证条件

出现以下任一证据时，应修正相应假设：

1. 某项默认忽略的环境因素实际改变命令能否运行、输出协议、session 行为、权限边界或其他核心结论；
2. 两种 CLI 无法使用一组共同的产品级检查问题，导致结果不可比较；
3. 仅比较最小坐标无法判断旧证据是否适用于新环境，且必须依赖更多稳定条件；
4. 为记录最小坐标必须读取敏感信息或运行 Agent 工作任务；
5. 后续实验无法在隔离临时目录中安全进行，或者无法避免与问题无关的外部副作用。

反证不会使已发生的历史观察消失，而会缩小结论的适用范围，并把新发现的必要变量加入相应实验记录。

## 验证方法与计划证据

本项只执行四项只读版本查询：

1. 读取 macOS 产品版本；
2. 读取芯片架构；
3. 读取 Codex CLI 版本；
4. 读取 Claude Code CLI 版本。

计划保存命令本身、成功退出事实和非敏感版本输出。不会查询可执行文件路径、Shell、运行时、网络、代理、配置、插件、Skill、MCP、账号或认证状态。

## 证据元数据、最小兼容性坐标与实验前提

证据元数据：验证日期为 `2026-09-02`。

| 最小兼容性坐标 | 计划证据 | 当前观察 |
| --- | --- | --- |
| macOS 版本 | `sw_vers -productVersion` | `26.5.2` |
| 芯片架构 | `uname -m` | `arm64` |
| Codex CLI 版本 | `codex --version` | `codex-cli 0.144.6` |
| Claude Code CLI 版本 | `claude --version` | `2.1.252 (Claude Code)` |

这些坐标只描述本轮证据的成立位置，不认证同坐标下所有机器一定表现一致。

## 后续共同评估协议

Stargazing 2 与 Stargazing 3 使用以下共同检查维度：

| 维度 | 必须回答的产品问题 |
| --- | --- |
| 启动 | Harness 能否无需人工操作终端发起一次工作 |
| 初始输入 | 如何传入一项明确工作及必要上下文 |
| 后续输入 | 如何把后续消息交给同一逻辑角色上下文 |
| 结果 | 如何取得可用结果或明确受阻结果 |
| 输出分层 | 内容、结构化事件、诊断信息与进程事实如何区分 |
| 连续性 | 同一角色的逻辑 session 如何标识、保持和恢复 |
| 隔离 | 不同角色的 session、工作目录和上下文是否互相污染 |
| 正常受阻 | Agent 正常返回“无法完成”时能观察到什么 |
| 调用故障 | 启动、连接、恢复或取得可靠返回失败时能观察到什么 |
| 结果未知 | 无法确认是否已产生结果或副作用时怎样诚实表达 |
| 超时 | 等待超过限制时由谁计时、得到什么事实 |
| 取消 | 请求停止后实际能阻止什么，不能撤销什么 |
| 并发 | 多个角色并行和同一角色多项工作分别有什么边界 |
| 工作目录 | 如何指定目录，Agent 实际可以访问什么范围 |
| 权限与工具 | 文件、命令、网络、MCP 和原生工具分别由谁控制 |
| 资源 | token、时长、调用次数或其他成本能观察和限制多少 |

共同维度不是最终 Harness 接口，也不要求两种 Agent 给出相同形式的答案。

## 单次实验的证据格式

后续每个实际实验至少记录：

1. 实验编号、日期和要回答的问题；
2. 本轮最小兼容性坐标；
3. 初始假设与反证条件；
4. 脱敏后的实际命令或调用参数；
5. 明确的工作目录和输入；
6. 相关 stdout、stderr、结构化事件和退出事实；
7. 调用前后可观察的文件或外部副作用；
8. 成功路径与至少一个相关失败路径，或无法安全验证的原因；
9. 观察事实、分析推断和当前建议，三者分开；
10. `可行`、`有条件可行`、`不可行`或`未决`结论；
11. 适用条件、未覆盖范围和触发重新验证的变化。

原始输出只有在非敏感、确有复核价值且适合提交时才保存；否则只记录足以复核的脱敏片段和退出事实。

## 后续实验安全规则

1. 默认使用系统临时目录中的人工样例，不把真实项目作为可写实验对象；
2. 未经用户单独授权，不执行 push、PR、发布、部署、通知、购买或其他外部副作用；
3. 不把凭证、环境变量值、账号、私有内容或未经脱敏的完整输出写入文档或 Git；
4. 每次实验记录实际工作目录和允许的文件操作；
5. 某项限制只有提示词约束时，明确标记为弱约束；只有 Harness 或可靠外部机制实际阻止时，才称为强制约束；
6. 发现意外副作用、权限越界或敏感输出时停止相应实验，先记录事实和收缩边界；
7. 临时探针只回答当前问题，不提前建设通用框架或产品代码。

## 默认忽略与证据驱动补充

默认不主动盘点：Shell、Node.js / Python 等运行时、安装路径、Git 版本、CPU 与内存、网络与代理、安装方式、全局配置、插件、Skill、MCP、账号套餐和调用额度。

“默认忽略”不表示已经证明这些因素无关。后续一旦观察到某项因素影响结果，应当：

1. 记录触发补充的具体观察；
2. 只在受影响的结论中增加该条件；
3. 重验受影响的最小范围；
4. 不把该条件无依据地推广到其他 Agent、版本或能力。

## 环境变化后的复验原则

1. 新环境先记录同一组最小兼容性坐标；
2. 坐标相同也不直接宣称行为必然相同，至少重跑当前要依赖的最小 smoke probe；
3. 坐标变化时，只重验可能受影响的能力；
4. 某项默认忽略因素已有影响证据时，把它纳入相应能力的复验条件；
5. 原环境结论永久保留为带日期和条件的历史证据，不因换电脑而改写；
6. 只有接入形态、session、输出协议或强制边界发生根本变化时，才考虑完整重验相关调研项。

## 当前观察

四项计划命令均成功退出并返回非敏感版本信息：

```text
$ sw_vers -productVersion
26.5.2

$ uname -m
arm64

$ codex --version

$ claude --version

```

本项没有读取 CLI 路径、Shell、运行时、网络、代理、配置、插件、Skill、MCP、账号、认证状态、套餐或额度；没有创建临时实验目录，因为未运行 Agent 工作任务；没有观察到需要补充为成立条件的其他环境因素。

## 当前结论

`可行`。

已经建立可供 Codex CLI 与 Claude Code CLI 后续边界实验共同使用的检查维度、证据格式、安全规则、默认忽略原则和环境变化复验原则，并取得本轮四项最小兼容性坐标。Stargazing 1 的进入下一层条件已经满足。

这个结论只表示评估协议与最小兼容性基线可以使用，不表示两种 CLI 已经满足 Harness 接入需要，也不表示当前机器已经通过全面环境检查。Codex CLI 与 Claude Code CLI 的任何程序化能力结论仍需分别通过 Stargazing 2 和 Stargazing 3 的真实成功与失败实验取得。

结论适用于本文记录的日期与最小坐标。换电脑或版本变化后，按本文复验原则重跑受到影响的最小范围；若后续发现其他环境因素实际影响结果，则收缩相应能力结论，而不回写或伪造本次观察。

## 尚未回答的问题

Codex CLI 与 Claude Code CLI 的程序化调用、连续 session、输出、故障、取消、并发、权限和资源边界均尚未验证，分别留给 Stargazing 2 和 Stargazing 3。两项可以在用户决定开始后并行推进，也可以按用户选择先验证其中一种。
