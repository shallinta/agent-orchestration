# Stargazing 9：阶段综合结论

日期：2026-09-09

状态：已完成（阶段完成提议及后续方向待用户审阅）

当前结论：有条件可行

性质：对 Stargazing 1–8 既有证据的综合审查，形成下一阶段建议；不是生产验收、完整架构或版本范围决定

## 要回答的问题

前八项技术证据是否共同支持 Harness 的核心价值——由成熟 Agent 负责语义判断，Harness 确定性传递协作事实，使真人不必逐轮搬运消息？哪些缺口必须阻止继续，哪些应成为具体能力交付前的验证门槛，哪些可以留待后续需求出现？

本项按[总计划](plan.md)收束已有探索，并以[Dreaming 阶段完成记录](../project-log/2026-08-31-dreaming-phase-completion.md)核对产品旅程。用户已授权开始本项；是否接受阶段完成提议、进入什么后续阶段，仍由用户审阅决定。

## 审查前假设与反证条件

当前假设：已有证据足以支持继续进入有边界的产品设计，但不足以证明完整产品可以交付，也不代表现有实验代码可以直接拼成生产 Harness。

以下任一情况会改变综合判断：

1. 真实连续协作依赖真人转发或 Harness 代替主持生成业务内容；
2. 保持连续性、公共能力和必要约束所需的条件彼此冲突，且没有已验证的组合路径；
3. 产品核心必须依赖尚无证据的全量工具代理、全局硬成本上限或完整外部副作用撤销；
4. 将独立假执行器实验误合并成真实 Agent 恢复、取消或生产稳定性保证；
5. 未验证的产品核心需求被误标为非核心，或建议只能靠未经用户确认的需求删除才成立。

## 方法、证据与完成条件

- 复核八项单项结论、真实成功与失败记录、版本与环境条件；必要时查阅对应可丢弃探针，不重新运行真实 Agent。
- 建立单项结论索引、用户旅程覆盖表、跨实验衔接检查和缺口处理表；每个结论都链接具体来源。
- 当前只综合已记录的历史证据，不查询或宣称最新 CLI 能力，不把今天作为旧实验的新验证日期。
- 由独立 Agent 复核主要推导和证据边界；校验文档链接、状态与差异。文档整理不增加运行实验，也不以重跑测试代替证据综合。
- 完成条件：形成四类结论之一，明确推荐方向、阻断条件和后续验证责任；同步索引、计划与手记；用户尚未作出的决定保持待审。
- 若发现必须追加实验的关键缺口，先记录具体问题、反证与安全边界，再按项目规则另行推进；本项不默认为所有未知补齐实验。

## 综合结果

**当前建议：继续进入产品设计。** 已有真实证据支持核心协作路径；可以据此设计如何使用这些能力，并把明确缺口转成对应能力的验证门槛。当前没有发现必须先否定项目方向或追加真实 Agent 实验才能开始设计的证据。

这个判断的对象是“是否值得且有依据继续设计”。完整产品可交付性、真实开发收益和长期无人值守可靠性仍未决。以下建议尚未成为用户确认的下一阶段决定。

## 四、局部证据能否衔接

### 1. 连续会话与公共能力：存在真实组合

SG6 实际使用专属 MCP、独立 session、逐次唤起与恢复，完成多轮委托和消息交付。因此 SG2/3 的调用能力与 SG5 的通道能力，已经不只是孤立成立。

不过配置必须按“组合”验证。SG3 的 Claude 无工具基线使用 safe-mode，SG5 发现它会一并移除显式 MCP，因此 SG5/6 使用另一组明确参数。Codex 的 ignore flags 没有消除所有 Skill 影响，SG6 曾因实际读取外部 Skill 停止，再以关闭 shell 的配置完成接受运行。旧单项中某个限制成立，不能推导组合后仍成立。

### 2. 连续协作与恢复：可以提出设计候选，未证明真实重启闭环

SG6 使用临时协作状态；SG7 使用独立 SQLite 探针与假 Adapter。它们没有共享一个经过崩溃恢复检验的运行系统。正常 turn 之间恢复 session、Harness 自身重启、真实 Agent 仍在执行时接管，是三个不同问题。

SG7 足以支持“先恢复事实、保留未知、不自动重派”的设计方向。若后续要提供重启后自动继续，就必须验证接受回执丢失、终态落盘、旧执行存活与真实 session 关联；仅把 SG6 状态换成 SQLite 不构成证据。

### 3. 连续协作与停止：旧进程组假设不能带入设计

SG8 的 Codex 与 MCP 独立进程组反例，使“启动一个进程组就控制了整次执行”这条路径不成立。该次实验依靠后续独立核验和人工处置清理残留，不能描述成已经支持无人值守的完整取消。

继续设计并不要求现在先实现完整进程追踪；但设计必须明确可控制范围和缺失证据时的行为。当前候选是持续注册和追踪受控执行组，或使用可靠取消句柄；尚未选定实现。宣布完整停止、释放相应执行槽或在同一角色继续工作之前，必须确认所承诺的执行范围已停止。停止无法确认与副作用未知不能混淆：前者不能谎报槽位已安全释放；后者在载体已确认停止后仍可独立核查，不永久占用槽位。

SG8 不证明 Codex 无法取消，也不证明 Claude 会出现同样进程布局。任何产品的后续取消保证都需相应实际证据。

### 4. 权限、自治与知识：通道内校验不等于全产品授权

SG5 拒绝身份注入和无权委托，只证明在既定通道映射下的确定性校验。没有验证平台用户登录、角色授权变化、查询过滤、审批请求与在途权限变化竞态，也没有覆盖 Agent 原生工具绕开 Harness 的全部能力。

既有 Dreaming 允许公开弱约束与未覆盖范围，因此缺少全量拦截不否定项目核心。但设计必须保留明确的权限范围与生效点；如果某场景要求强读取隔离、原生工具逐次审批或全局硬成本上限，现有证据不足以放行该场景。

### 5. 技术可行与实际收益：仍需真实使用检验

SG6 主持确实针对首次交付追问并吸收修正，这是有价值的语义协作证据。但其目标、角色和材料均预设，没有写真实代码，未作人工基线或单 Agent 对照，不能推导节省多少时间、token 或费用，也不能保证质量总是提升。

首次启动失败链中主持曾错误声称委托已履行；明确故障提示后的成功，只证明该样本遵守规则。该提示是实验场景规则，不把“主持永远不能自行执行”变成产品要求。成果质量与目标判断仍由 Agent 或真人负责，不能借综合调研引入程序化验收。

## 五、缺口分级与后续处理

以下是 Agent 的分析建议，尚不决定具体版本范围或安排新的实验。

| 缺口 | 是否阻止进入设计 | 什么时刻必须补足 | 所需最小证据方向 |
| --- | --- | --- | --- |
| 不完整的真实执行停止与动态进程组 | 否；必须排除旧父组假设 | 宣称完整取消、强制停用，或依赖停止确认开展无人值守真实工作前 | 对选定产品和工具组合验证所承诺范围的终止、残留检测、失败暴露和清理；Codex 与 Claude 分别验证 |
| 送达未知、真实 session 与 Harness 恢复的衔接 | 否 | 提供重启后自动继续或宣称 Harness 跨中断重试安全前 | 在明确崩溃窗口检验不丢已提交事实、不误认终态、不重复派发；无证据时保持未知并交由决策 |
| 真实代码协作、共享产物与使用收益 | 否 | 声称满足初始开发场景或确实节省协调成本前 | 用用户认可的实际需求观察设计、执行、独立评审和修复；同时记录用户介入、用时、成本来源与质量问题 |
| 目标确认、用户审批、平台/角色授权 | 否 | 交付相应治理能力或开放真实副作用前 | 验证明确批准与拒绝的效果、权限范围、等待/恢复、重复或迟到输入；确认不能靠沉默或模型推断产生 |
| 快照与知识检索层 | 否；仍属产品核心 | 交付这部分已确认能力前 | 验证从记录维护派生知识、追溯依据、更新过时内容、受控查询与失败可见；不承诺全知或绝对正确 |
| 可控资源的硬限制与成本覆盖 | 否 | 宣称任何硬预算保证前 | 明确计量单位及范围、可阻止的调用入口、并发占额和未知用量；CLI 客户端估算不能替代全局账单上限 |
| 强文件/网络隔离、原生工具审批 | 对普通有边界设计不阻断；特定场景可能阻断 | 场景依赖这些强保证前 | 由适用外层机制或产品能力取得直接证据；不以提示词和参数名代替 |
| 远程 Agent、跨机器与非 macOS 接入 | 不阻止本地 CLI 候选的设计 | 宣称对应接入已受支持前 | 第三个完整 Agent 的程序化边界、连续性、身份与结果、网络故障和取消事实；裸模型 API 不替代 Agent |
| 长期多角色并发、同 workspace 冲突与生产耐久性 | 否 | 支持相应并发规模或生产可靠性承诺前 | 对具体状态/产物方案验证竞争、背压、故障恢复和限流；不从两个短任务外推 |

这张表区分的是验证门槛，不是永久优先级。远程接入等未覆盖方向也没有被从愿景中删除。若用户下一步选择的场景立即依赖某项强保证，该行就成为那个场景的前置阻断项。

恢复与重试门槛针对 Harness 自己需要作出的判断，不把成熟 Agent 的内部重试循环纳入 Harness 全量接管，也不把已明确未启动的故障与送达/结果未知合并。

当前建议不追加 SG9 实跑：已有反证已经足以排除错误方案，而剩余最小实验需要先明确准备承诺什么具体行为。围绕尚未选择的完整保证继续增加探针，会扩大范围，仍无法自动证明完整产品。

## 六、可以带入设计的候选边界

1. 保留每种 Agent 的专属适配责任，让 Harness 依赖可追溯的共同事实；不预选类、包、进程或共享 driver 形式。
2. 角色、具体执行与连续性引用保持明确关联；连续性丢失不能静默创建新 session 冒充恢复。
3. 角色专属 STDIO MCP 是当前证据最强的公共能力候选；结构化返回请求有双端往返证据。CLI/HTTP 若采用，需要补齐其缺失的 Agent E2E 与凭据证明。
4. 普通消息、委托责任、调用故障、Agent 结果和治理确认保持独立；语义判断归角色，结构校验与事实处理归 Harness。
5. 停止请求、停止确认、结果、槽位、副作用与重试资格分开；实际未知不能被映射成成功、失败或自动重派。
6. 已提交事实与语义派生视图分开；知识维护需要明确来源和权限，不能用会话里的一份总结代替完整事实记录。
7. 权限、审批、资源预算按覆盖范围公开保证来源；任何强制边界失效必须可见，不能静默变成提示词约束。
