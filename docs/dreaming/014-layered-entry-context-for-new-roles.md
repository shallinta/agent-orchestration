# Dreaming 14：新角色通过分层入场上下文进入已有 Thread

日期：2026-08-25

状态：当前阶段共识，可继续修正

## 这次只讨论什么

这次只讨论新角色加入一个已经持续运转的 thread 时，默认需要获得怎样的协作起点，以及谁负责判断哪些已有信息与新角色相关。

本次不决定入场上下文的格式、协议、存储方式、上下文窗口大小、具体权限结构或其他技术实现。

## 角色可以在 Thread 生命周期中随时加入

角色不必在 thread 创建时一次性全部加入。协作推进、目标变化或长期跟踪过程中，都可能需要引入新的角色。

按照 Dreaming 12，thread 可以长期存在，并先后跨越多个权威目标。一个后加入的角色面对的可能不是刚开始的协作，而是已经积累了大量消息、事件、委托、决定和进展快照的持续上下文。

因此，新角色不能只被告知“你已经加入”，还需要获得足以开始承担当前职责的入场上下文。

这里的“随时加入”表示角色不受 thread 创建阶段限制，可以在生命周期中的不同阶段加入；它不改变谁有权引入角色，也不表示主持自动获得自主引入权。入场上下文传递的是当前协作信息，不表示新角色继承任何旧角色的身份、记忆或会话连续性。

## 全量历史与单一快照都不足以作为默认入场方式

把 thread 的全部历史一次性提供给新角色，会引入大量与当前职责无关或已经过时的信息，增加噪声，使角色难以识别真正需要关注的目标、决定和工作。

但只提供最新进展快照同样不可靠。按照 Dreaming 13，进展快照是 Agent 或真人生成的语义派生工作视图，可能过时、遗漏事实或包含角色判断，不能替代完整记录。

因此，默认入场方式既不是完整历史全量灌入，也不是把最新快照当作唯一真相，而是提供一个分层的协作起点。

## 默认入场上下文采用分层内容

新角色加入已有 thread 时，默认获得的入场上下文包括：

1. 当前权威目标。如果当前没有活跃的权威目标，应如实说明当前无活跃权威目标；只有目标确实正在讨论时，才进一步说明正在讨论，不能把候选目标写成权威目标。
2. 已经确认并且与当前协作有关的关键决定。快照或消息中的普通判断不能仅因被选入入场上下文而成为已确认决定。
3. 如果已经存在进展快照，提供最新一份，并明确标注它是语义派生视图，可能过时、遗漏或包含角色判断，需要在必要时回到事实来源核对；如果尚未产生任何进展快照，则明确说明当前暂无可用快照。
4. 与该角色职责相关的当前委托，以及用于继续了解这些工作的上下文入口。
5. 由主持推荐查询的消息记录、其他事实记录或知识关键字，帮助角色按需深入了解背景。

这里确认的是默认需要覆盖的产品信息层次，不是在决定固定模板、显示顺序、字段、链接形式或传递协议。

## 入场上下文不是完整历史的替代品

新角色不会因为加入 thread 就自动接收完整历史。入场上下文先提供能够开始工作的相关信息，避免无差别灌入长期累积的全部内容。

同时，入场上下文也不会缩窄角色原有的查询权限。角色可以在自身权限允许的范围内主动查询并核对完整消息、事件和委托记录，也可以查询可用的 thread 上下文或知识库。入场上下文中提供的最新快照、关键决定和主持推荐线索都不能取代这种事实核对。

主持推荐某些记录或知识关键字，是相关性建议，不表示角色只能查询这些内容。角色能查到什么，仍由 Dreaming 9 所确认的角色权限决定。

## 主持负责作出语义选择

主持负责理解新角色为什么加入、将承担什么职责，并据此判断哪些已确认决定是关键的、哪些当前委托与它相关、哪些记录或知识关键字值得优先查询。

这些选择需要理解目标、历史和角色职责，属于语义判断。主持可以根据协作变化调整推荐，但不把一次推荐变成角色永久只能看到的范围。

Harness 不理解消息含义，也不自行判断哪些历史最重要或最适合新角色。它只依据主持已经作出的选择、明确记录的权威状态和角色权限，提供并展示相应入场信息。这里确认的是职责边界，不决定信息如何组装、传递或调用。

## 与既有记录、快照和权限边界保持一致

入场上下文不会修改或删减 Dreaming 9 所确认的完整 thread 记录。新角色是否直接收到某项内容，与完整记录是否存在仍是两个不同问题。

如果入场上下文提供了最新进展快照，它仍保持 Dreaming 13 的派生属性。被展示给新角色不会使它自动成为权威结论，也不会让其中的遗漏从完整记录中消失。

新角色对完整记录、thread 上下文和知识库的主动查询范围继续受角色权限约束。入场上下文提供的是默认协作起点，不会自动扩大权限，也不会因为没有默认包含某项历史就自动禁止角色在权限范围内查询它。

这一分工也与 Dreaming 11 一致：主持承担相关性与重要性的语义判断，Harness 只执行明确选择和权限规则，不进行语义筛选。

## 这项共识暂时不意味着什么

- 不意味着新角色会自动收到完整 thread 历史。
- 不意味着最新进展快照足以单独代表当前事实或权威结论。
- 不意味着已经决定入场上下文的固定模板、字段或显示顺序。
- 不意味着已经决定消息、事件、委托、快照或知识如何被引用和组装。
- 不意味着已经决定任何协议、接口、命令或传递流程。
- 不意味着已经决定入场上下文采用何种存储形式或文件布局。
- 不意味着已经决定 Agent 的上下文窗口如何使用、裁剪或压缩。
- 不意味着已经决定具体的角色权限结构、默认权限或授权流程。
- 不意味着主持推荐的查询记录或知识关键字会成为临时访问限制。
- 不意味着 Harness 会理解内容、评估相关性或自动选择“最重要”的历史。
- 不意味着新角色会继承任何旧角色的身份、记忆或会话连续性。
- 不意味着已经改变谁可以引入角色，或主持已经获得自主引入权。

入场上下文的表达与展示、各层信息的具体形式、角色查询体验、权限细节和上下文窗口使用，留给后续 Dreaming 或设计阶段继续讨论。
