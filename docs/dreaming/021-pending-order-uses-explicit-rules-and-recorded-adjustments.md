# Dreaming 21：待处理顺序由明确规则与可记录调整共同决定

日期：2026-08-26

状态：当前阶段共识，可继续修正

## 这次只讨论什么

这次只讨论角色释放主动执行能力后，多个待处理内容之间的下一项顺序如何形成，以及确定性 Harness 与 Agent、真人的语义判断怎样分工。

本次不决定具体默认顺序、优先级模型、调整权限范围、跨角色排序、饥饿与公平、抢占、自动启动、通知、UI、协议、状态机、算法或其他实现方式。

## 下一项顺序有确定性基线

当角色释放出主动执行能力，并且存在多个待处理内容时，需要有明确顺序说明哪一项排在下一位置。无特别指示时，Harness 使用稳定的默认顺序规则。

“稳定”表示 Harness 按照明确、可重复的规则形成顺序，不随机选择，也不阅读消息或委托内容后自行猜测哪一项更重要。

本轮不决定默认顺序的具体规则，也不确认默认是否采用 FIFO。这里只确认必须存在一个不依赖 Harness 语义判断的确定性基线。

默认顺序说明下一项待处理内容的先后位置，不表示达到该位置后必然自动启动执行。是否以及何时开始主动执行仍受角色并发能力、可用状态和其他适用约束影响。

## 明确、可记录的语义调整可以改变顺序

稳定默认顺序无法理解业务紧急程度、依赖关系或当前目标。主持或持有这些待处理内容的目标角色，可以基于语义判断显式调整顺序。

语义判断属于主持、目标角色背后的 Agent 或真人；Harness 只接受并应用已经明确表达的调整结果。调整必须成为明确、可记录的行为，不能只存在于某个角色心中的判断，也不能要求 Harness 从一句含糊的自然语言中猜出新的先后关系。

角色可以说明调整理由，但 Harness 不需要理解理由才能执行明确结果。即使消息内容看起来“紧急”“重要”或“阻塞其他工作”，只要没有形成明确有效的顺序调整，Harness 就继续使用当前适用的顺序规则。

主持与目标角色分别可以调整哪些范围、需要什么权限、发生冲突时以谁为准，以及调整是否有持续期限，本轮均不决定。

## 明确规则与语义调整共同形成当前顺序

待处理顺序由稳定默认规则提供确定性基线，并由当前有效、明确记录的顺序调整在允许范围内改变。没有特别调整时使用默认规则；存在有效调整时，Harness 按明确结果执行，不自行重新解释业务含义。

这种共同作用不是让 Harness 一半依赖规则、一半自行理解内容。语义判断在进入 Harness 之前已经由 Agent 或真人完成，Harness 看到的是明确的调整结果。

多个调整怎样组合、旧调整何时失效、调整与后来到达内容如何共同形成顺序，都属于后续问题。本轮不设计优先级模型、冲突解决规则或排序算法。

## 待处理内容不是统一数据实体或队列

“待处理内容”是对角色已经接收、但尚未开始主动处理的普通消息和委托的集合性描述。它方便讨论角色接下来先关注什么，不表示普通消息与委托被合并成同一种数据实体、记录或队列。

普通消息继续承担沟通作用，不天然产生需要持续跟踪的责任。委托继续是 Dreaming 10 所定义的独立工作责任，拥有自己的发布者、唯一目标角色和生命周期。

Harness 可以对不同待处理内容表达先后关系，不等于它们在持久化、权限、状态或产品语义上变成同一种事物。具体如何跨普通消息与委托形成默认先后，本轮也不决定。

## 调整顺序不改变原有语义与责任

顺序调整只改变待处理内容被考虑或开始处理的先后，不改变普通消息表达的内容，也不改变委托的责任、发布者、目标角色、验收权或生命周期。

把一项委托调到较后位置不会取消或拒绝它，也不会把责任转移给其他角色；把一条普通消息调到较前位置也不会让它自动成为委托。

取消委托、拒绝委托、请求调整委托或将工作另行委托给其他角色，仍然是 Dreaming 10 中各自明确的行为，不能由顺序调整隐式产生。顺序变化也不会自动合并、拆分或完成任何委托。

## Harness 只应用明确结果，不猜测重要性

Harness 负责按照当前适用的确定性顺序规则和明确、可记录的调整结果，形成并应用待处理先后关系。它可以记录谁在何时作出了什么调整，但不评价调整理由是否充分，也不从内容推导未被明确表达的新优先级。

顺序调整行为及其产生的可确定变化继续按照 Dreaming 9 进入完整 thread 记录。这使后续角色能够知道当前顺序为何不同于默认基线，但不会把调整理由自动升级为事实或权威结论。

这一分工延续 Dreaming 11：语义选择只由 Agent 或真人作出，Harness 只执行机器可识别的明确规则与结果。当某项调整无效或权限不明确时，Harness 不能自行补全或猜测这项调整，仍只依据当前有效规则执行；具体反馈与处理方式留待后续讨论。

## 与 Dreaming 20 保持一致

Dreaming 20 确认角色繁忙时仍可接收普通消息和委托作为待处理内容，并发能力只限制同时主动执行数量。Dreaming 21 进一步说明：当主动执行能力释放后，下一项先后由确定性基线与明确调整共同决定。

本轮只确认顺序如何形成，不确认内容是否自动进入主动执行，也不决定排序、调度与角色并发能力之间的具体调用流程。

## 这项共识暂时不意味着什么

- 不意味着普通消息和委托被合并成统一数据实体、记录或队列。
- 不意味着顺序调整会改变普通消息或委托的产品语义。
- 不意味着顺序调整会改变委托责任、发布者、目标角色、验收权或生命周期。
- 不意味着顺序调整会自动取消、拒绝、转移、拆分、合并或完成委托。
- 不意味着 Harness 会根据内容猜测紧急程度、重要性或业务依赖。
- 不意味着已经决定稳定默认顺序是什么，也不意味着已经选择 FIFO。
- 不意味着已经决定优先级模型，或主持、目标角色分别可以调整哪些范围。
- 不意味着已经决定多个调整的冲突关系、失效条件或与新增内容的组合方式。
- 不意味着已经决定跨角色排序、饥饿与公平、抢占或自动启动。
- 不意味着已经决定通知、UI、接口、协议、状态机、算法、模块或实现方式。

具体默认顺序、顺序调整权限与范围、多个调整的组合、跨角色关系、公平与抢占、自动启动和通知行为，留给后续 Dreaming 或设计阶段继续讨论。
