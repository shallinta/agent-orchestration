# Dreaming 32：权威目标只统一要求两项最低内容

日期：2026-08-26

状态：当前阶段共识，可继续修正

## 这次只讨论什么

Dreaming 31 确认主管理员可以直接提交并确认目标，也可以确认主持整理的目标候选，但两条入口都需要满足同一份最低内容要求。本次只讨论所有场景都必须具备哪些最低内容，以及哪些常见信息不应成为全局必填。

本次确认每个权威目标都必须包含`预期结果`和`完成判断依据`。其他内容可以根据场景补充或引用，但不要求每个简单目标都填写一份完整目标包。

本次不决定字段名、数据类型、字数、具体格式、引用规则、内容充分性由谁评价、确认交互、UI、接口、协议、数据结构、状态机或实现。

## 最低内容一：预期结果

`预期结果`说明这次协作最终希望产生什么结果，或者希望现实、项目、资料、产品、认识或其他对象发生什么状态变化。

它回答的是“最终想得到什么”，而不是强制要求主管理员预先写出详细工作步骤。一个目标可以指定必须采用的方案，也可以把方案留给后续设计，但至少要让角色知道协作应当朝什么结果推进。

例如，“按照已经确认的技术方案完成某功能开发”可以表达预期结果；具体方案可以通过明确引用关联，而不必复制进目标正文。仅写“继续处理”“看看这个”或“尽快推进”，如果没有其他明确内容能够说明期待什么结果，就不足以构成可确认目标。

本轮不要求预期结果必须量化，也不要求它只能描述单一产物。复杂目标可以包含相互关联的多项结果，只要它们仍共同构成主管理员想要推进的当前目标。

## 最低内容二：完成判断依据

`完成判断依据`说明主管理员届时依据什么判断目标已经达到、相关成果可以接受。

它可以是明确的客观证据，例如测试通过、指定数据达到条件、材料已经交付或某项外部检查完成；也可以是质量要求、指定角色的评审结果，或者明确说明由主管理员对最终成果进行主观验收。

完成判断依据不要求所有目标都被数字化，也不等于 Harness 可以自动判断目标完成。即使依据是客观证据，主持仍负责结合目标和成果提议完成，主管理员仍负责确认目标是否达到、成果是否可以接受，继续遵守 Dreaming 12。

如果目标只说想得到什么，却完全没有说明如何判断已经足够，参与角色可能不断追加工作或对完成产生不同理解。因此这项内容与预期结果一起构成所有目标都需要的最小共同参照。

## 两项内容都存在才满足最低要求

被主管理员确认的目标必须同时具有预期结果和完成判断依据。只有其中一项，不满足 Dreaming 31 所说的最低内容要求。

两项内容可以非常简短，也可以通过明确引用 thread 中已经存在的方案、文档、消息或其他资料来补充。最低要求关注的是必要语义是否存在，不要求所有相关信息都复制进目标正文。

内容在形式上存在，不一定表示它在语义上已经充分、没有歧义或没有风险。Harness 将来是否只校验两项内容存在，主持怎样评价和提示其质量，属于后续产品设计与实现问题，本轮不决定。

## 其他内容按场景补充或引用

以下信息经常有价值，但不适合成为所有权威目标的统一必填：

- 背景与动机；
- 范围与明确非目标；
- 预期产物及其形式；
- 业务规则和其他限制；
- 指定方案、参考资料和已有决定；
- 风险、假设与仍待确认事项；
- 时间期望、截止要求与优先级输入。

主持可以根据场景建议主管理员补充其中一项或多项，也可以在目标候选中主动整理它们。复杂、高风险或跨多角色的目标通常需要更多信息，简单明确的目标则可能只用一两句话表达完整。

“不是全局必填”不表示这些信息不重要，也不表示主持应当忽略明显缺失。它只表示 Harness 产品不要求所有场景为了形式统一而填写同一份重型目标表。

## 最低内容不等于完整需求或计划

目标确认意味着参与者已经有一个共同、权威的推进方向和完成参照，不意味着需求分析、方案设计、任务拆分或所有未知问题都已经结束。

权威目标确认后，主持仍可以组织必要的分析、设计、评审和计划；执行中也可能发现新信息并建议主管理员更新目标。最低内容要求只保证目标可以成为共同参照，不试图在确认时提前装入整个后续协作过程。

这保持了两种用户体验：想法模糊的用户可以先在 thread 内探索，再逐渐形成目标；已经准备充分的用户可以用很短的目标直接确认并尽快进入推进。

## 这项共识暂时不意味着什么

- 不意味着权威目标只允许包含预期结果和完成判断依据。
- 不意味着背景、范围、非目标、产物、限制、方案、资料、风险、假设或时间信息不重要。
- 不意味着所有目标必须填写同一份完整需求表或项目立项模板。
- 不意味着预期结果必须量化、只能包含一项结果或必须预先指定执行方案。
- 不意味着完成判断依据必须量化、必须能够自动检查或排除主管理员主观验收。
- 不意味着存在客观完成依据时 Harness 就能自动确认目标完成。
- 不意味着形式上存在两项内容就保证目标语义充分、无歧义或没有风险。
- 不意味着已经决定字段名、格式、引用方式、内容评价责任、确认控件、UI、接口、协议、数据结构、状态机、算法、模块或实现。

目标内容怎样引用其他资料、主持何时应当建议补充可选信息，以及权威目标确认后怎样形成第一批推进安排，留给后续 Dreaming 继续讨论。
