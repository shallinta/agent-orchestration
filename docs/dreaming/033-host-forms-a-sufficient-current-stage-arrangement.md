# Dreaming 33：目标确认后形成足以推进当前阶段的安排

日期：2026-08-26

状态：当前阶段共识，可继续修正

## 这次只讨论什么

Dreaming 31 和 Dreaming 32 已经说明权威目标怎样确认、至少包含什么。本次继续讨论：目标确认之后，主持是否必须先制定覆盖全程的详细计划，还是可以用更敏捷的方式开始推进。

本次确认主持需要形成足以推进当前阶段的安排，并根据结果持续调整；它不要求预先预测完整生命周期，也不是完全脱离整体目标逐项临时反应。

本次不决定安排的固定内容、模板、表达形式、更新频率、展示方式，也不决定 UI、接口、协议、数据结构、状态机、模块或实现。

## 不要求先制定覆盖完整目标的详细计划

权威目标确认后，主持不必等到目标的全部阶段、任务、依赖、风险和角色分工都已经被完整预测并写成详细计划，才可以开始协作。

许多工作只有经过资料查询、方案分析、试验、首轮实现或评审后，才能知道真正的下一步。强制一开始覆盖完整生命周期，容易制造虚假的确定性，也会让简单目标承担不必要的规划成本。

这并不否定完整计划在某些场景中的价值。主管理员已经提供明确方案、目标高度可预测或风险要求事前整体评审时，主持仍可以形成较完整的计划；只是 Harness 产品不把它作为所有目标开始推进的统一前置条件。

## 也不应完全逐项临时反应

不要求完整计划，不表示主持可以脱离权威目标，只根据最新一条消息随意发布下一项委托。

主持需要结合当前权威目标、已有事实、角色能力和约束，形成一份足以推进当前阶段的安排。它至少应帮助主持理解当前最需要解决的事情、哪些工作能够开始、哪些依赖尚未满足，以及当前结果怎样被带回整体目标中判断。

主持还应考虑现有角色是否适合承担近期工作、是否缺少需要申请或引入的角色、结果需要怎样检查或评审，以及在能够预见时，最近一次可能需要主管理员作出决定的节点。

这些是阶段推进安排应发挥的作用，不是本轮已经确定的固定字段或必填模板。简单目标可能通过一项清楚的委托就完整表达当前安排；复杂目标才可能需要一段阶段说明、多项并行委托或更完整的协作计划。

## 阶段安排随结果持续调整

主持在第一阶段获得新事实、交付、评审意见、失败信息或风险后，应重新理解它们对当前目标的影响，并形成下一阶段足够的安排。

因此，阶段推进安排天然可以演进。主持不需要为了忠于早期计划而忽略后来证据，也不需要每次变化都重新规划尚不可知的全部后续工作。

调整工作步骤、角色分工、先后关系、检查方式或近期阶段，一般只是在权威目标内部改变推进方法，不自动构成目标变化。只有预期结果或完成判断依据等权威目标内容确实需要变化时，才继续按照 Dreaming 8 和 Dreaming 31 请求主管理员确认更新。

## 简单目标与复杂目标使用同一原则

对于简单明确的目标，足以推进当前阶段的安排可能只有一个动作，例如把已经确定的实现工作委托给合适角色，并说明如何回报和检查。此时没有必要为了形式完整而制造多阶段计划。

对于复杂目标，主持可以先安排需求分析、方案设计、风险调查或首轮试验，再根据结果决定后续开发、评审、测试与修正。它可以清楚说明当前只承诺近期安排，后续会随事实继续展开。

两类场景使用的是同一原则：计划深度服务于当前推进需要，而不是由 Harness 要求所有 thread 采用相同粒度。

## 阶段推进安排不是新的系统实体

本轮使用“阶段推进安排”描述主持应当形成的协作认识与近期行动组织，不要求新增一种与消息、委托、目标或进展快照并列的系统实体。

安排可以通过主持的普通消息、清楚发布的一个或多个委托、已有方案的引用，或其他普通 thread 协作行为表达。复杂场景是否值得形成单独文档，是角色根据实际需要作出的选择，不是本轮确立的通用要求。

具体工作责任仍由委托表达并持续跟踪。阶段推进安排不会取代委托，也不会因为提到某个角色可能负责一项工作，就自动形成委托责任。

## 目标确认后不自动增加计划审批

主管理员确认权威目标，不意味着主持随后形成的阶段推进安排必须统一再经过一次主管理员审批。

一项安排或其中具体行动是否需要批准，继续由当前适用的角色权限、审批策略和资源预算决定。审批策略要求批准时必须等待有效批准；没有这项要求时，主持可以在已有边界内启动工作。

这避免每个目标都固定经历“目标确认—计划确认—开始执行”三段式流程，让主管理员能把日常协调交给主持。高风险或高成本场景仍可通过通用审批策略保留必要控制。

## Harness 不评价阶段安排

理解目标、选择当前阶段、判断依赖、挑选角色、决定检查方式和识别主管理员决策点，都属于主持的语义判断。

Harness 继续负责消息与委托路由、持久化以及角色权限、审批策略、资源预算等确定性规则。它不评价阶段安排是否周全、顺序是否合理，也不替主持选择下一项业务工作。

如果主持没有形成足够安排、选择错误或需要改进，应由主管理员或其他角色通过 thread 协作指出和纠正，而不是由 Harness 理解内容后自动修复。

## 这项共识暂时不意味着什么

- 不意味着所有权威目标开始推进前都必须形成覆盖完整生命周期的详细计划。
- 不意味着不需要任何整体认识，或者主持可以脱离权威目标逐项临时反应。
- 不意味着阶段推进安排必须成为独立系统实体、正式文档或固定格式。
- 不意味着安排中提到某个角色就已经形成对该角色的委托责任。
- 不意味着调整阶段安排会自动修改当前权威目标。
- 不意味着目标确认后统一增加一道主管理员计划审批。
- 不意味着权限、审批和预算在目标确认后失效。
- 不意味着 Harness 会理解、评价、修正阶段安排或替主持选择业务步骤。
- 不意味着已经决定安排字段、模板、更新频率、展示方式、通知、UI、接口、协议、数据结构、状态机、算法、模块或实现。

主持怎样在已有角色中选择首批执行者、缺少合适角色时如何向主管理员表达人才需要，以及结果返回后怎样决定评审与下一阶段，留给后续 Dreaming 继续讨论。
