# Dreaming 30：目标确认前允许主持组织探索性协作

日期：2026-08-26

状态：当前阶段共识，可继续修正

## 这次只讨论什么

Dreaming 29 确认主持从收到主管理员的初始意图开始承担推进责任。本次继续讨论：在权威目标尚未形成或确认时，主持能否委托其他角色参与，以及“只开展探索、不把未确认目标当作既定目标推进”的边界由谁承担。

本次确认主持可以组织探索性协作；探索边界属于主持标签职责提示中的语义行为规范，不是 Harness 根据工作内容施加的专门硬限制。提示词可能被误解或未被遵守，这项风险在目标确认阶段可以接受。

本次不决定主持标签使用的具体提示词、怎样表达探索目的、探索包含哪些固定活动、主管理员以什么频率查看进展或如何纠正，也不决定 UI、接口、协议、状态机、模块或实现。

## 目标确认前可以委托其他角色

权威目标尚未确认，不表示主持只能与主管理员进行一对一澄清。主持可以根据当前初始意图和已有信息，向 thread 中其他合适角色发布普通委托，也可以使用普通消息、资料查询和多角色讨论等已经存在的协作能力。

这些协作可以用来理解现状、收集事实、识别未知、检验假设、比较可能方向、发现限制或形成目标候选。探索结果帮助主管理员与主持更好地决定要做什么，而不是要求用户先独自完成全部需求分析再允许其他角色参与。

目标确认前发布的委托仍是 Dreaming 10 定义的普通委托，保留发布者、唯一目标角色、交付、验收和生命周期等既有语义。本轮不新增“探索委托”类型，也不因为工作发生在目标确认前就把普通沟通和委托合并。

主持应当让受托角色理解当前工作的探索目的和已知背景，使结果服务于目标形成。但具体说明内容和形式由主持作语义判断，本轮不规定固定模板。

## 探索边界属于主持职责提示

“只开展帮助形成目标的探索，不把未确认目标当作既定目标全面推进”需要理解工作目的、结果含义和当前业务情境，因此属于主持的语义判断与行为责任。

这项责任应当成为主持系统标签附带职责提示的一部分。主持需要理解当前仍处于目标形成阶段，判断哪些问题值得探索，组织适当角色参与，并避免把自己的目标猜测冒充主管理员已经确认的权威目标。

这里提到职责提示，只记录已经想到的产品约束承载位置，不在 Dreaming 阶段设计具体提示词内容、拼接方式、优先级或运行机制。

普通受托角色可以根据主持给出的上下文完成探索工作、提出异议或指出目标假设不可靠，但它们不会因为参与探索而获得权威目标确认权。

## Harness 不识别探索语义

Harness 不读取自然语言后判断一项委托究竟是探索、正式执行还是主持已经越过了目标确认边界，也不根据这种内容分类对委托施加专门门禁。

Harness 继续负责普通消息与委托的路由、持久化和明确结构校验，并执行当前适用的角色权限、审批策略、资源预算及其他确定性规则。它可以知道当前是否存在已经确认的权威目标这一客观状态，但不能仅凭该状态推导一项具体工作在业务上是否适合作为探索。

角色权限、审批策略和资源预算始终有效，并可能阻止某项探索行动；但它们是适用于各阶段的通用自治边界，不是 Harness 为“探索性协作”新增的内容识别规则。

本轮不要求结构化标记每项委托是否属于探索，也不创建一套与普通委托并行的探索生命周期。

## 提示词约束不是确定性保证

主持标签的职责提示能够表达预期行为，但不能像 Harness 校验明确权限或预算一样提供确定性保证。主持可能误解初始意图、错误判断当前工作范围，或者过早把某个目标候选当成既定方向推进。

当前接受这种误判风险，不为了消除它而要求 Harness 理解业务内容或建立专门的探索门禁。否则需要让确定性程序判断“探索”和“全面执行”的语义区别，既难以可靠完成，也会破坏 Dreaming 11 已确认的职责边界。

已经发生的探索、误判、委托和结果都继续进入完整 thread 记录。纠正不会删除或改写已经发生的事实，也不会让未确认目标因曾被执行过就自动取得权威地位。

## 主管理员在目标确认阶段投入更多注意力

之所以接受提示词无法硬性保证探索边界，一个重要前提是：在目标形成和确认阶段，主管理员本来就会比稳定执行阶段投入更多精力关注 thread 进展。

主管理员可以观察主持提出的问题、组织的探索、目标候选和明显偏离，并及时澄清意图、纠正误解、要求调整方向或阻止不合适的继续推进。这个阶段的人类参与符合 Dreaming 2 的目标：人不是彻底离开协作，而是在定向、价值判断和风险接受等关键位置投入注意力。

主管理员投入较多注意力，不表示它必须亲自安排每次探索、阅读每条消息或逐项审批所有委托。具体是否需要审批继续取决于已有审批策略；主管理员关注进展与 Harness 强制逐项门禁是两回事。

当权威目标确认、协作进入相对稳定的推进阶段后，主管理员可以把更多日常协调交给主持，只在新的关键决定、风险或目标变化时重新投入。具体关注方式和频率本轮不决定。

## 这项共识暂时不意味着什么

- 不意味着权威目标确认前只能由主管理员和主持进行两人对话。
- 不意味着主持在目标确认前不能向其他角色发布普通委托。
- 不意味着需要新增“探索委托”实体、类型或独立生命周期。
- 不意味着探索结果、主持总结或受托角色结论会自动成为权威目标。
- 不意味着 Harness 会理解委托内容、判断探索目的或阻止主持语义上的误判。
- 不意味着主持标签的职责提示能够提供与权限门禁相同的确定性保证。
- 不意味着角色权限、审批策略和资源预算在探索阶段失效；它们仍是通用的确定性边界。
- 不意味着主管理员必须亲自组织、阅读或逐项审批全部探索工作。
- 不意味着已经决定主持提示词、探索范围清单、进展关注方式、纠正流程、通知、UI、接口、协议、状态机、算法、模块或实现。

目标候选应当以什么内容呈现给主管理员、主管理员确认权威目标时需要理解哪些信息，以及确认后主持如何转入稳定推进，留给后续 Dreaming 继续讨论。
