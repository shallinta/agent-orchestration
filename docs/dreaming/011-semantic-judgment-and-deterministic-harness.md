# Dreaming 11：语义判断属于角色，Harness 负责确定性执行

日期：2026-08-20

状态：当前阶段共识，可继续修正

## 这次只讨论什么

这次只讨论 thread 协作中语义判断与确定性执行分别由谁承担，以及 Harness 识别到客观事实事件后默认应当通知谁。

本次不设计模块、接口、协议、状态机或具体策略表达，也不决定事件分类与路由配置的完整形式。

## Harness 不承担语义判断

Harness 是确定性程序，不承担意图识别。理解自然语言、判断一个结果表达了什么或质量如何、根据业务语义选择下一步，只能由 Agent 或真人承担。

真人在 thread 内参与这些判断时，通过自己的用户角色发言或行动。平台用户在 thread 之外通过 UI 或 API 执行的明确配置操作则是显式指令；Harness 可以按指令执行，不需要也不应猜测平台用户没有明确表达的意图。

这条边界意味着 Harness 不会因为读到一句自然语言，就自行推导其中隐含的目标、责任、质量结论或业务动作。需要理解含义的地方，必须交给相应 Agent 或真人角色判断。

## 主持承担协作推进中的整体语义判断

主持负责理解 thread 的整体目标、评估各角色交付的结果、决定下一项委托、识别需要用户作出决策的时刻，并判断何时可以提议完成 thread。

“提议完成”不表示主持可以单方面结束 thread。主持只能基于协作情况提出完成建议；thread 最终如何被结束、需要谁以何种方式确认，不在本次 Dreaming 中决定。

主持可以借助 Harness 获得消息、委托进展和客观事实事件，但这些事实不会替主持作出语义判断。例如，“当前没有活跃委托”不等于“目标已经实现”，仍需主持结合目标与成果判断下一步。

## Harness 承担确定性的协作执行

Harness 负责校验结构化信息与权限，路由消息和事件，持久化 thread 记录，并按照明确配置执行并发控制、等待与超时、失败重试、审批门禁和定时触发等确定性工作。

这些职责的共同点是：所需条件、边界和动作能够被明确表达，Harness 只依据已经给出的信息与配置执行，不需要理解自然语言含义或评价业务结果。本次只确认产品职责，不据此决定任何模块或调用方式。

## Harness 识别客观事实，不判断业务含义

Harness 可以识别由明确记录或规则确定的客观事实事件，例如：

- 委托已经超时；
- 一次 Agent 或外部服务调用已经失败；
- 当前没有活跃委托；
- 配置的检查点已经到达。

Harness 不能据此判断一份方案是否足够好、thread 目标是否已经实现，或下一步应当开发、评审还是采取其他业务行动。这些结论需要 Agent 或真人结合语义作出。

## 自动策略必须有明确且有限的边界

Harness 可以自动执行具有明确条件、次数、时间和权限边界的确定性策略。例如，一项失败处理策略可以规定在什么条件下、以什么权限、最多重试多少次；只要规则覆盖当前事实，Harness 就可以继续执行预先明确的动作。

Harness 不得无限自行处理。策略完成、达到次数或时间边界、权限不满足，或者出现规则未覆盖的情况后，Harness 应当停止继续推演，持久化已经发生的事实，并把事实报告给相应角色，由 Agent 或真人判断后续动作。

报告只陈述可确定的信息，例如失败原因、已经执行的次数和当前状态。Harness 不自行编造解决方案，也不把未被规则覆盖的下一步伪装成确定性结论。

## 客观事实事件有默认归属

事件的默认接收者由事件类型和相关对象的既有归属决定：

- 委托级事件，例如委托超时、被拒绝、目标角色请求调整或重试耗尽，默认发送给该委托的发布者；根据明确的事件规则或配置，在需要时同步目标角色。
- Thread 级事件，例如当前没有活跃委托、整体停滞或检查点到达，默认发送给主持。
- 审批事件发送给配置中明确指定的审批角色。

Thread 配置可以显式覆盖这些默认路由。Harness 只依据事件类型、对象归属和明确配置选择接收者，不判断“谁最适合解决这个问题”。如果某个事实最终需要主管理员决策，应由主持或相关角色识别并向主管理员提出，而不是由 Harness 根据消息含义自行推断。

“整体停滞”怎样成为可确定事件、哪些委托级事件需要同步目标角色，以及完整事件分类如何形成，都仍是未决问题；在规则明确之前，Harness 不能凭语义自行判断。

## 所有事件进入完整 thread 记录

无论一个事件默认发送给谁、是否被配置改写路由，所有事件都按照 Dreaming 9 的共识进入完整的 thread 持久化记录。

直接接收者与完整持久化仍是两个不同问题：路由决定谁会直接收到事实报告，持久化确保 thread 生命周期内发生的事件不会因定向发送而从完整记录中消失。

## 这项共识暂时不意味着什么

- 不意味着 Harness 会理解自然语言、评价结果质量、确认目标已经实现或选择业务下一步。
- 不意味着主持可以单方面结束 thread；当前只确认主持可以判断何时提议完成。
- 不意味着“无活跃委托”会自动触发 thread 完成或证明协作已经停滞。
- 不意味着 Harness 可以在没有明确条件、次数、时间或权限边界时持续重试或自行解决问题。
- 不意味着 Harness 会为失败、超时或未覆盖情况自行生成解决方案。
- 不意味着已经决定策略如何表达、默认重试或处理次数是多少。
- 不意味着已经穷举全部事件类型，或已经决定事件路由配置的具体形式。
- 不意味着已经决定整体停滞如何判定、检查点如何工作或通知通过什么渠道送达。
- 不意味着已经决定任何模块、接口、协议、状态机、事件结构或调用流程。

确定性策略的表达与默认边界、完整事件分类、路由覆盖方式、停滞判定、检查点细节和通知渠道，留给后续 Dreaming 或设计阶段继续讨论。
