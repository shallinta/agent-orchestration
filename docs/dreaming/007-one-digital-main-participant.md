# Dreaming 7：每个 Thread 同时只有一个主持

日期：2026-08-13

状态：当前阶段共识，可继续修正

## 这次只讨论什么

这次只讨论 `主持` 在 thread 中的产品含义、职责边界，以及用户能否更换承载主持标签的角色。不讨论拥有主持标签的角色如何获得指引、如何完成交接，也不讨论其权限或运行方式如何实现。

`主持`是附加在角色上的唯一系统标签，不是角色本身，也不是身份卡永久拥有的属性。本文中的“主持”均指这一系统标签。

## 一个 Thread 同时只有一个主持

每个 thread 在任意时刻有且只有一个主持。用户创建 thread 时选择一张 Agent 身份卡，由它产生 Agent 角色并附加主持标签；当前需求中，主持只能附加在 Agent 角色上。

唯一主持为整项协作提供一个持续、明确的推进中心。它避免多个角色同时争夺整体推进职责，也避免所有角色都只完成局部工作、却没有角色持续关注 thread 是否正在接近共同目标和预期成果。

## 主持负责整体推进

拥有主持标签的 Agent 角色类似一名协作主持人或 PMO。它持续关注整个 thread，而不只完成其中一项业务任务。主持职责包括：

- 理解 thread 当前的共同目标、预期成果和约束；
- 根据协作需要拆分工作，并把工作分派给合适的角色；
- 吸收各角色的结果，将其带回整体目标中理解；
- 根据当前进展判断下一步需要做什么；
- 识别需要用户作出价值判断、承担风险或最终确认的时刻；
- 在不需要用户介入时持续推动协作向前，而不是让用户重新成为日常协调者。

这些职责描述的是主持应当为用户带来的协作效果，不表示已经确定具体的工作步骤或推进方式。

## 主持是 Thread 内叠加的系统标签

主持不是一种独立于身份卡的永久身份，而是附加在某个 thread Agent 角色上的整体推进职责。

同一张 Agent 身份卡可以在一个 thread 中产生承载主持标签的角色，也可以在另一个 thread 中只产生不承载主持标签的普通角色。某张身份卡产生的角色曾经承载主持，不意味着它以后参加任何协作时都天然拥有这一系统标签。

因此，身份卡描述角色可能具备的身份和特征；主持则是用户针对当前 thread 指定的系统标签。

## 主持不是业务身份或最高权力

拥有主持标签的角色负责组织和推进协作，但不因此成为业务上的最高负责人，也不自动拥有高于其他角色的最终决定权。

真人老板、产品经理、编辑、游戏主持人等仍可以作为用户角色加入 thread，并在各自领域中提供目标、规则、判断或决定。拥有主持标签的 Agent 角色负责让这些人与其他角色形成连续协作，而不是取代他们的业务身份。

主管理员仍然是关键节点的最高判断者和本次 thread 的最终责任人。其他用户角色可以参与业务判断，但不自动拥有最高治理权。主持应当识别何时需要主管理员介入，而不能因为负责整体推进就替主管理员接受本应由其决定的价值取舍或风险。

## 主管理员可以更换主持

主管理员可以在 thread 进行过程中把主持标签转移给另一个 Agent 角色。更换承载主持标签的角色不会创建新的 thread，也不会让既有协作、目标、进展和角色关系从头开始。

更换改变的是哪个 Agent 角色继续承担整体推进职责，而不是否定这项有界协作此前已经发生的部分。如何让前后两个角色完成充分交接、原来承载主持标签的角色之后是否继续承担其他工作，留到后续讨论。

## 将主持附加在用户角色上是远期未验证扩展

当前不把主持标签附加在用户角色上的场景纳入需求。一方面，让真人承担持续理解全局、吸收结果、判断下一步和推动协作的职责，会带来明显更高的协作复杂度；另一方面，这类需求是否真实存在、能够覆盖多大规模，目前都缺少证据。

已知的候选场景通常可以由“拥有主持标签的 Agent 角色负责整体推进，真人业务角色负责业务主持或关键判断”来覆盖。例如真人老板、产品经理或游戏主持人可以继续拥有其业务身份，同时由 Agent 角色承担持续协调工作。

因此，把主持标签附加在用户角色上只作为远期、需要重新验证的扩展可能保留，不作为当前 Harness 必须满足的场景。

## 这项共识暂时不意味着什么

- 不意味着已经决定拥有主持标签的角色使用什么提示词、身份说明或内置身份卡。
- 不意味着已经决定主持如何拆分、分派、吸收结果或判断下一步。
- 不意味着已经决定更换主持时的交接内容、交接时机或异常处理。
- 不意味着已经决定主持相关权限如何表达或执行。
- 不意味着主持拥有所有业务问题的最终决定权，也不意味着它可以越过用户的关键判断。
- 不意味着原来承载主持标签的角色在更换后必须离开 thread，或必须继续作为普通角色。
- 不意味着真人永远不能承担主持职责，只是当前没有足够证据把主持标签扩展到用户角色。

主持如何与其他角色共同形成具体协作过程、何时需要用户介入，以及 thread 如何走向结束，留给后续 Dreaming 继续讨论。
