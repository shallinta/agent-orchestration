# Dreaming 7：每个 Thread 同时只有一名数字主参与者

日期：2026-08-13

状态：当前阶段共识，可继续修正

## 这次只讨论什么

这次只讨论主参与者在 thread 中的产品含义、职责边界，以及用户能否更换主参与者。不讨论主参与者如何获得指引、如何完成交接，也不讨论其权限或运行方式如何实现。

## 一个 Thread 同时只有一名主参与者

每个 thread 在任意时刻有且只有一名主参与者。用户创建 thread 时指定由哪一名参与者担任主参与者；当前需求中，主参与者必须是数字 Agent。

唯一主参与者为整项协作提供一个持续、明确的推进中心。它避免多个参与者同时争夺整体推进职责，也避免所有参与者都只完成局部工作、却没有人持续关注 thread 是否正在接近共同目标和预期成果。

## 主参与者负责整体推进

主参与者类似一名协作主持人或 PMO。它持续关注整个 thread，而不只完成其中一项业务任务。它承担的职责包括：

- 理解 thread 当前的共同目标、预期成果和约束；
- 根据协作需要拆分工作，并把工作分派给合适的参与者；
- 吸收各参与者的结果，将其带回整体目标中理解；
- 根据当前进展判断下一步需要做什么；
- 识别需要用户作出价值判断、承担风险或最终确认的时刻；
- 在不需要用户介入时持续推动协作向前，而不是让用户重新成为日常协调者。

这些职责描述的是主参与者应当为用户带来的协作效果，不表示已经确定具体的工作步骤或推进方式。

## 主参与者是 Thread 内叠加的职责

主参与者不是一种独立于身份资料卡的永久身份，而是叠加在某个 thread 参与者之上的整体推进职责。

同一张身份资料卡可以在一个 thread 中产生主参与者，也可以在另一个 thread 中只产生普通参与者。某张资料卡曾经担任主参与者，不意味着它以后参加任何协作时都天然拥有这一角色。

因此，身份资料卡描述参与者可能具备的身份和特征；是否担任主参与者，则由用户针对当前 thread 指定。

## 主参与者不是业务角色或最高权力

主参与者负责主持和推进协作，但不因此成为业务上的最高负责人，也不自动拥有高于其他参与者的最终决定权。

真人老板、产品经理、编辑、游戏主持人等仍可以作为业务参与者加入 thread，并在各自领域中提供目标、规则、判断或决定。数字主参与者负责让这些人与其他参与者形成连续协作，而不是取代他们的业务身份。

用户仍然是关键节点的判断者和最终责任人。主参与者应当识别何时需要用户介入，而不能因为负责整体推进就替用户接受本应由用户决定的价值取舍或风险。

## 用户可以更换主参与者

用户可以在 thread 进行过程中指定另一名数字参与者接替主参与者职责。更换主参与者不会创建新的 thread，也不会让既有协作、目标、进展和参与者关系从头开始。

更换改变的是谁继续承担整体推进职责，而不是否定这项有界协作此前已经发生的部分。如何让前后两名主参与者完成充分交接、原主参与者之后是否继续承担其他工作，留到后续讨论。

## 真人主参与者是远期未验证扩展

当前不把真人担任主参与者纳入需求。一方面，让真人承担持续理解全局、吸收结果、判断下一步和推动协作的职责，会带来明显更高的协作复杂度；另一方面，这类需求是否真实存在、能够覆盖多大规模，目前都缺少证据。

已知的候选场景通常可以由“数字主参与者负责整体推进，真人业务参与者负责业务主持或关键判断”来覆盖。例如真人老板、产品经理或游戏主持人可以继续拥有其业务角色，同时由数字主参与者承担持续协调工作。

因此，真人主参与者只作为远期、需要重新验证的扩展可能保留，不作为当前 Harness 必须满足的场景。

## 这项共识暂时不意味着什么

- 不意味着已经决定主参与者使用什么提示词、角色说明或内置资料卡。
- 不意味着已经决定主参与者如何拆分、分派、吸收结果或判断下一步。
- 不意味着已经决定更换主参与者时的交接内容、交接时机或异常处理。
- 不意味着已经决定主参与者、普通参与者和用户之间的权限如何表达或执行。
- 不意味着主参与者拥有所有业务问题的最终决定权，也不意味着它可以越过用户的关键判断。
- 不意味着原主参与者在被更换后必须离开 thread，或必须继续作为普通参与者。
- 不意味着真人永远不能担任主参与者，只是当前没有足够证据把它纳入本项目需求。

主参与者如何与其他参与者共同形成具体协作过程、何时需要用户介入，以及 thread 如何走向结束，留给后续 Dreaming 继续讨论。
