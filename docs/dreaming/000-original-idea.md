# Dreaming 0：用户最初构想原文

日期：2026-08-12

性质：历史输入档案

以下内容逐字保存用户在项目讨论开始时给出的构想。它用于避免项目起点因时间推移而被遗忘或稀释，不表示其中所有想法都已成为共识，也不随之后的认识变化而改写。

---

我想做一个 Agent 编排harness工具/引擎，主要编排目标是 cli 类和可远程调用类的 agent，不包含桌面app类的agent。最主要用户场景是项目开发中，每个需求的各个步骤，如需求分析、设计、方案评审、开发、代码评审、测试、问题查询、问题修复等等，可以根据用户配置的不同agent资料（如使用模型、擅长领域、执行速度等），把每个步骤按需分配给不同 agent 来执行，并让不同agent交叉评审，甚至一起进行问题分析和讨论，让速度快的agent来做执行，质量高的来做方案和评审，推理强的来做分析，实现质量和速度兼备的自动化开发，最后沉淀项目公共经验，不断积累业务逻辑知识，更好的应对未来需求。另外，在非代码类的项目中，希望也可以使用，例如自媒体创作、数据分析、金融投资等，核心是多agent合作场景。要求：用户可以自定配置添加 agent 身份资料卡，为每个agent设置名称、性格、回复风格、发言权重、擅长方向、特征属性、调用方法等，其中调用方法支持 cli 和 远程接口调用两种，cli 类预设 codex cli 和 claude code cli 两个。每个需求通常使用一个新的生命周期，称为 thread，在一次生命周期中，用户需要首先指定一个主agent，用于整体需求流程推进、任务拆分与分派、外部调用（如消息通知等）、进展记录与资料沉淀、定时提醒等，harness 负责在各个agent之间“传话”、解析外部调用并执行（如发通知、把agent生成内容展示到某个前端UI上等）、并行控制、脑暴模式控制（多 agent 进行分析讨论的场景，可能考虑广播、轮流、两两对话、主持人等模式，还没想清楚，可能需要边做边试验效果）、定时任务、持久化存储等。用户自己可加入 thread 中进行对话，harness 需要处理用户的发言（可当做一个特殊的身份资料卡，但提高发言权重）。前端UI 与harness核心执行逻辑分离，通过通信机制来同步，目前准备用 electrobun 来开发并使用 [https://github.com/shallinta/electrobun-app-starter](https://github.com/shallinta/electrobun-app-starter) 来打底，但前期先跑通纯 harness 核心功能，然后再做前端UI，且 harness核心功能应该不依赖特定前端UI，而是以几个固定输入输出通信协议与前端UI交互，可随时接入其他前端UI，例如网页UI 或飞书、telegram 等三方聊天工具，这可以参考 openclaw 的架构实现。在一个 thread 中，可以有一种固定时间检查点或类似的机制，harness在这个检查点汇总所有agent新发生的信息，沉淀到进展文档（一个thread对应一个），用户可随时查看（通过通信机制、前端UI或直接文件系统等方式）。

这目前还是一个大概的想法，很多细节还没有想清楚，需要你跟我逐步讨论并记录。对于本项目，我希望的推进方式是，采用敏捷开发的方式，不一步到位做一个大而全的方案，而是从最最核心的一小点功能开始，讨论想法，对齐设计，记录文档，敏捷开发和验证，提出反馈意见和建议，快速迭代，从 v0.0.1开始维护版本号。未来还会考虑自行开发一个专门针对编排场景的主agent，内置为身份资料卡给用户选择使用。本项目其中一个目标是在一次项目需求中充分利用市面上多个流行的、来自顶级大厂（如A社、OpenAI、Deepseek等）的agent的优秀能力，如 codex，claude code 等，而不是自己开发一个agent，因为个人开发永远比不上大厂agent的能力上限。适合类比的场景是，我现在开发需求时，会同时使用 codex（配gpt-5.6-sol 模型）和 claude code（配国产 deepseek v4 模型），其中前者是顶级模型，考虑全面、能力强大，但缺点是速度慢，适合做方案设计和评审，而后者接国产模型优势是调用速度飞快，给定充分的方案和限制后代码开发快而好，缺点是做方案或评审时容易疏漏，所以我会让 codex 写方案，然后拆分任务，然后手动复制给 claude code 去执行写代码，然后又手动告诉 codex 去做代码评审，然后手动把问题告诉 claude code 去修改，如此反复，最终提交的质量不错，但我的时间也没节省太多，主要都充当消息转发员了，因此才想做这个项目，把中间分派任务给不同agent、及撰写提示词的工作，交给一个主agent，把消息转发和进展汇报交给一个 harness（即本项目核心），充分自动化，把自己抽身出来，只做重要节点签字和决策（如方案最终评审、上线准出等）。
