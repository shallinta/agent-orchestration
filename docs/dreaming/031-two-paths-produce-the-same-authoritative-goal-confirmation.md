# Dreaming 31：权威目标通过两条入口形成同一种确认事实

日期：2026-08-26

状态：当前阶段共识，可继续修正

## 这次只讨论什么

Dreaming 8 已经确认只有主管理员能够确认当前权威目标，Dreaming 29 和 Dreaming 30 又确认目标可以从模糊初始意图和探索性协作中形成。本次继续讨论：主管理员已经清楚知道目标时是否仍必须经过主持复述，以及普通目标表达怎样与正式确认区分。

本次确认权威目标有两条形成入口：主管理员直接提交并确认，或者主持整理候选后由主管理员确认。两条入口最终产生同一种明确、可追溯的目标确认事实。

本次不决定权威目标的最低内容要求、固定字段、格式、目标候选模板、确认交互、UI、接口、协议、数据结构、状态机或实现。

## 权威目标必须经过明确确认

一项内容成为当前权威目标，必须发生主管理员明确执行的目标确认。该行为属于 thread 内角色治理，不是平台用户在 thread 外修改 Thread 配置。

目标确认必须清楚指向将被确认的目标内容，并作为完整 thread 记录中可追溯的治理事实保留。沉默、模糊赞同、允许探索继续、开始讨论方案或后续已经发生执行，都不能被反向推断为主管理员确认了某个目标。

Harness 可以依据已经明确发生的确认事实保存和提供当前权威目标，但不从普通自然语言中猜测主管理员是否已经表达确认，也不评价目标内容是否合理、充分或值得执行。

最低内容要求未来可能包含可由 Harness 确定性校验的存在性条件，也可能包含需要角色判断的语义质量；具体边界本轮不决定。

## 入口一：主管理员直接提交并确认

当主管理员已经清楚知道想要实现什么，并且准备的目标内容满足当前适用的最低要求时，可以一次性直接提交并确认该目标。

这种入口适合较简单明确的执行动作，也适合主管理员已经准备好技术方案、创作要求、分析框架或其他充分材料的场景。例如，主管理员可以明确要求按照已经给出的技术方案完成开发，并把这一要求作为当前权威目标直接确认。

直接确认本身已经完成目标治理行为，不需要主持为了形式完整而机械复述同样内容，再要求主管理员重复确认一次。否则越明确、越简单的工作反而需要越多无价值交互，与减少用户协调负担的产品目标相悖。

主持收到直接确认的目标后，仍然负责理解、组织和持续推进。主持发现矛盾、遗漏、风险或更好方向时，可以提出问题并建议修改，但这些意见不会自动撤销、暂停或改写已经确认的当前权威目标。

如果确实需要改变目标，继续遵守 Dreaming 8：只有主管理员再次明确确认更新，新的内容才取代此前权威目标。

## 入口二：主持整理候选后请求确认

主管理员也可以先用普通自然语言表达需求、愿望、方案或执行意图，而不同时执行正式目标确认。

即使一句表达在语义上看起来非常明确，例如“按照这个方案开发”，只要它没有明确作为满足最低要求的目标被主管理员提交并确认，就仍然只是 thread 内输入，不能由 Harness 或主持自行升级为权威目标。

主持可以结合主管理员的表达、已有材料、探索结果和其他角色意见，整理出满足最低要求的目标候选，并明确交给主管理员确认。主管理员可以确认、要求调整或否决，只有明确确认后才形成当前权威目标。

这条入口服务于想法尚不完整、目标内容缺少必要信息，或者主管理员希望主持帮助归纳的场景。它不是所有目标都必须机械经历的固定两轮流程。

## 两条入口产生同一种治理结果

直接提交并确认与主持辅助形成候选，只是权威目标在确认前经历的不同用户旅程，不会产生两种等级、可信度或效力不同的目标。

无论采用哪条入口，最终都必须由主管理员明确确认同一份目标内容，并形成同一种当前权威目标与可追溯确认事实。后续角色不需要因为目标来自直接确认还是主持候选，就采用不同的服从、质疑、修改或完成规则。

主持可以帮助判断普通输入是否已经接近可确认状态，但不能替主管理员确认；Harness 可以记录明确确认，却不能从内容语义判断确认是否发生。两者职责继续保持分离。

## 最低内容要求用于减少歧义，不制造重型流程

两条入口都要求被确认的目标满足一份最低内容要求。它用于确保角色至少知道要朝什么结果推进，并为后续判断目标是否变化、成果是否可接受提供共同参照。

最低内容要求不应被自动理解为完整需求文档、详细执行计划或所有未知问题都已经解决。简单目标可以很短，只要必要信息齐全；复杂目标则可以引用已经存在的方案、资料和约束，而不必把所有内容复制进目标正文。

具体哪些内容必须存在、哪些内容可以引用、哪些内容只在特定场景需要，以及不满足时由谁指出，本轮不决定，留给下一项 Dreaming 讨论。

## 这项共识暂时不意味着什么

- 不意味着所有目标都必须先由主持复述，再由主管理员进行第二次确认。
- 不意味着主管理员说出的每句要求、方案或执行指令都会自动成为权威目标。
- 不意味着 Harness 会从自然语言、沉默或后续行为中推断目标确认。
- 不意味着直接确认形成的目标比主持候选形成的目标具有更高效力。
- 不意味着主持在目标直接确认后不能提出问题、风险或修改建议。
- 不意味着主持的建议可以自行撤销、暂停、改写或取代已经确认的目标。
- 不意味着目标确认属于平台用户修改 Thread 配置。
- 不意味着已经决定目标最低内容、固定字段、格式、模板、确认控件、UI、接口、协议、数据结构、状态机、算法、模块或实现。

权威目标需要包含哪些最低内容、主管理员确认时必须理解哪些信息，以及目标确认后主持怎样形成第一批推进安排，留给后续 Dreaming 继续讨论。
