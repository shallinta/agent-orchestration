# Dreaming 29：主持从初始意图开始承担推进责任

日期：2026-08-26

状态：当前阶段共识，可继续修正

## 这次只讨论什么

这次从一条完整理想用户旅程的第一个交接点开始，讨论用户什么时候可以不再亲自承担日常协调工作，以及主持从什么时刻开始对协作推进负责。

本次只确认：在典型旅程中，主管理员向已经创建的 thread 表达初始意图后，主持就开始承担理解、澄清、组织和持续推进责任，不需要等待完整需求、权威目标或执行方案已经形成。

本次不决定主持使用什么固定提示词、按什么问题清单澄清、采用多少轮对话、怎样呈现目标候选，也不决定 UI、接口、协议、状态机、模块或实现。

## 用户可以从不完整的初始意图开始

Thread 创建完成后，主管理员不需要先提交一份结构完整的需求、明确无歧义的权威目标或已经评审过的执行方案，才可以开始实质协作。

主管理员可以先表达一段初始意图。它可以只是一个尚未解决的问题、一种模糊愿望、一批背景资料、已经知道的限制，或者这些内容的零散组合。用户无需先把它加工成 Harness 或 Agent 专用的格式。

初始意图是协作的起始输入，不是权威目标。它的价值在于让主持和其他角色能够开始帮助用户理解问题，而不是要求用户在获得协作帮助之前先独自完成需求分析。

Dreaming 8 已经确认 thread 可以先存在，再在协作中形成目标。本轮进一步明确：主持的推进责任也不以权威目标已经形成或确认作为起点。

## 主持从收到初始意图开始接手日常协调

在典型旅程中，主持收到主管理员的初始意图后，就开始承担理解当前输入、识别关键未知、组织必要讨论并推动协作逐渐形成可确认目标的责任。

这个时点是用户与主持之间第一次真正的协调责任交接。用户不必继续亲自把每条输入重写成不同 Agent 的提示词，不必自行决定先问谁、下一步讨论什么，也不必在每轮输出后重新充当消息转发者。

如果现有信息还不足以形成可靠目标候选，主持可以向主管理员提出关键问题，也可以在角色权限、审批策略、资源预算和其他 Thread 配置允许的范围内，组织已有角色参与分析或讨论。

如果现有信息已经足够，主持可以整理出目标候选、重要背景、限制、预期成果和仍待确认事项，交给主管理员判断。具体采用提问、讨论、资料查询还是直接整理，不由 Harness 根据自然语言内容自行决定。

主持的持续推进责任并不等于无条件持续执行。如果主管理员的初始意图明确要求先记录、等待或暂不行动，正确理解并维持这一要求本身也是主持职责的一部分。

## 接手推进不等于取得目标确认权

主持从初始意图开始负责推动协作，不表示它可以把自己的理解、总结或目标候选直接变成权威目标。

Thread 中的任何角色仍可提出、质疑和完善目标。主持负责组织这些输入，并使待确认内容逐渐清楚；只有主管理员能够确认哪个目标表述成为当前权威目标。权威目标后续发生变化时，也继续需要主管理员确认。

因此，主持的责任开始得早，但治理权没有因此扩大：它可以在目标尚未确认时主持形成目标，不能代替主管理员作出最终决定。

## 接手推进不等于自动获得行动权限

主持承担推进责任，不会绕过当前适用的角色权限、审批策略、资源预算与其他 Thread 配置。

主持可以判断需要提问、讨论、查询资料、引入人才或开始某项工作，但这些行动能否直接发生，仍取决于对应的权限、审批和预算边界。需要批准或新增角色时，继续遵守已经确认的申请与治理规则。

这避免把“用户可以尽早交出协调责任”误解成“主持可以在目标未确认时不受约束地消耗资源或执行高风险行为”。前者是产品希望减少的用户负担，后者属于自治边界，两者不能混为一谈。

## Harness 不理解初始意图

初始意图通常是自然语言或其他非结构化资料，其理解、提问、归纳和目标候选形成都属于 Agent 或真人角色的语义判断。

Harness 负责把输入传递给主持，持久化相关消息与事件，并按照明确的角色权限、审批、预算和其他规则执行可确定行为。Harness 不判断用户的想法是否清楚，不替主持选择问题，也不决定何时已经足以形成目标候选。

这继续遵守 Dreaming 11 的边界：角色负责意图理解与业务判断，Harness 负责确定性执行。

## 其他角色仍可参与目标形成

主持从主管理员的初始意图开始承担推进责任，不意味着目标形成只能是主管理员与主持之间的两人对话。

已经加入 thread 的其他 Agent 角色和用户角色仍可以补充资料、提出问题、质疑假设或参与讨论。主持负责使这些参与服务于当前问题，并把形成的认识带回主管理员需要确认的内容中。

如果缺少适合当前分析或讨论的角色，是否引入新角色以及主持能否自主引入，继续由现有 Thread 配置、权限和此前未决边界决定，本轮不新增权限。

## 这项共识暂时不意味着什么

- 不意味着创建 thread 时必须已经有权威目标、完整需求或执行方案。
- 不意味着初始意图必须采用固定模板、字段或结构化格式。
- 不意味着主持必须等到权威目标确认后才开始理解、提问、组织或推进协作。
- 不意味着主持可以把初始意图、自己的总结或其他角色的提议自行确认为权威目标。
- 不意味着主持接手推进后可以绕过角色权限、审批策略、资源预算或其他 Thread 配置。
- 不意味着 Harness 会理解自然语言意图、判断信息是否充分或替主持选择澄清问题。
- 不意味着目标形成只能由主管理员和主持两名角色完成。
- 不意味着主持必须无条件立即执行；主管理员明确要求记录、等待或暂不行动时，主持仍应遵守。
- 不意味着已经决定主持提示词、目标候选格式、澄清清单、对话轮数、通知、UI、接口、协议、状态机、算法、模块或实现。

主持如何判断信息是否已经足以从目标澄清转入后续工作，以及权威目标确认后如何形成第一批可执行协作安排，留给后续 Dreaming 继续讨论。
